# 상속과 생성자 체인

- 생성자 new()가 하는 일
- 자식 객체를 생성할 때 구동되는 생성자 순서

## Constructor: new()

ex) base b = new();
하는 일 두가지

- **할당**: 객체를 만들고 핸들이 가리키게 함
- **new() 내부 코드 실행**: 그 객체의 멤버를 초기화

```
Child c = new();


c ──► [ Child 객체 ]      할당 1번
        x   ← Base에서 물려받은 멤버   (Base::new가 초기화)
        y   ← Child 자신의 멤버        (Child::new가 초기화)
```

| 표현          | 의미                                                    |
| ------------- | ------------------------------------------------------- |
| `c = new();`  | 객체 할당 + 생성자 코드 실행                            |
| `c = new a;`  | 객체 할당 + `a`의 멤버 값 복사 (생성자 실행 안 함)      |
| `super.new()` | 할당 없음. 현재 객체에서 부모 부분의 생성자 코드만 실행 |

### Constructor Chain

자식 클래스 생성자(new())가 실행되면 부모의 생성자 코드도 자동 실행됨

- 어떻게? 컴파일러가 자식 클래스의 new() 문 **제일 첫줄**에 super.new()를 넣음(호출)
- 조건: 부모 생성자에 필수인자가 없어야 함
- 인자가 있다면: 컴파일러는 어떤 값을 넣어야하는지 모름
  자식 클래스의 new() 문에 super.new(argments)를 반드시 써줘야 함
- 컴파일 에러

따라서 p1에서 Base::new가 출력된 뒤에 Child::new가 출력됨
하지만 super.new()가 실행된다고 해서 부모의 객체가 생기는 것은 아님 객체 할당은 없음

```
c ──► [ Child 객체 ]
|........ x (자식에서 선언한 변수)
|........ y (부모에만 선언한 변수)
```

> [!Note]
> uvm_component들 new()함수에 name과 parent 넣는게 필수인 이유

## Overide

부모에 있는 메서드와 같은 이름으로 메서드를 만든 경우

- 자식 타입 핸들로 부모에만 정의해둔 메서드를 접근한다면? -> 부모 바로 받아옴 (위 그림 참고)
- 자식에도 같은 이름과 인자로 만든 메서드가 있다, method()를 실행한다면? -> 자식에게 정의해둔 메서드 실행
- 부모의 것을 실행시키려면 super.method()로 실행함
